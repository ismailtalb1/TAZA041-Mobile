# TAZA 041 — تطبيق الزبون (النسخة المحسّنة للموبايل)

تطبيق Flutter رسمي يحافظ على هوية ومسارات موقع الزبون `taza041_web` ويرتبط مباشرةً بواجهات Laravel نفسها، مع تنظيم تنقل أكثر ملاءمة لتطبيقات الهاتف.

## الفرق التصميمي عن النسخة المطابقة

- شريط تنقل سفلي ثابت للمستخدم المسجل: الرئيسية، المنيو، الطلبات، والحساب.
- عناوين AppBar وسطية ومسارات أقصر للوصول إلى الوظائف الأكثر استخدامًا.
- بقيت الألوان والخطوط والبطاقات والمحتوى ومنطق العمل مطابقًا للموقع والنسخة الأساسية.

## الوظائف

- الرئيسية للضيف والمستخدم، العربية والإنكليزية، والوضع الفاتح والداكن.
- التسجيل، الدخول، استعادة كلمة المرور، وتخزين جلسة الدخول بصورة آمنة.
- المنيو والعروض والسلة والطلبات العادية.
- التوصيل مع تحديد الموقع، احتساب المسافة والتكلفة، وتعيين السائق من الإدارة.
- حجز الطاولات العادية وVIP والتحقق من التوفر.
- الدفع النقدي أو بنقاط الولاء، وسجل الطلبات والإلغاء والتقييمات.
- الإشعارات، الملف الشخصي والنبذة والصورة، العناوين السريعة، نقاط الولاء، والمساعد الذكي.
- محتوى الرئيسية وصفحة «عن المطعم» يتزامن مع المحتوى الذي يديره مدير التواصل في الداشبورد.
- صور وهوية بصرية مستخرجة من موقع الزبون من دون تعديل الموقع أو الـBackend.

تفاصيل مطابقة المسارات موجودة في [docs/API_MATRIX.md](docs/API_MATRIX.md).

## التشغيل المحلي

المتطلبات: Flutter `3.41` أو أحدث، Android SDK حديث، وJava `17` أو أحدث (Android Studio JBR 21 مناسب).

```bash
flutter pub get
flutter run --dart-define=TAZA_API_BASE=http://10.0.2.2:8000/api
```

العنوان أعلاه لمحاكي Android. استعمل عنوان IP لجهاز التطوير عند التشغيل على هاتف حقيقي. في نسخة المتجر يجب أن يكون العنوان HTTPS:

```bash
flutter run --dart-define=TAZA_API_BASE=https://example.com/api
```

## الفحص

```bash
dart analyze
flutter test
```

اختبارات الواجهة تشغّل جميع الشاشات بعروض `360dp` و`390dp` و`430dp` وتتحقق من عدم ظهور استثناءات layout أو overflow.

## إصدار Android للمتجر

1. أنشئ upload keystore واحفظه خارج المشروع.
2. انسخ `android/key.properties.example` إلى `android/key.properties` وضع القيم الحقيقية. الملف الفعلي مستثنى من Git ولا يجب رفعه.
3. استخدم مزود خرائط إنتاجي أو tiles مستضافة ذاتيًا؛ رابط OpenStreetMap الافتراضي مناسب للتطوير والاستخدام الخفيف فقط.
4. ابنِ الحزمة:

```bash
flutter build appbundle --release \
  --dart-define=TAZA_API_BASE=https://example.com/api \
  --dart-define=TAZA_MAP_TILE_URL=https://maps.example.com/{z}/{x}/{y}.png
```

لا تنشر Release قبل إضافة مفتاح التوقيع الفعلي. إعداد Android يمنع HTTP الصريح في نسخة الإنتاج، بينما يسمح به debug فقط للتطوير المحلي.

## إصدار iOS

يُبنى من macOS/Xcode بعد ضبط Team وBundle Identifier وشهادات Apple، ثم:

```bash
flutter build ipa --release \
  --dart-define=TAZA_API_BASE=https://example.com/api \
  --dart-define=TAZA_MAP_TILE_URL=https://maps.example.com/{z}/{x}/{y}.png
```

## ملاحظات Backend الحالية

- طرق الدفع الإلكتروني `Syriatel Cash` و`Sham Cash` ظاهرة بهوية الموقع لكنها معطلة بوضوح لأن الـBackend الحالي يرفض تفعيلها بحالة `423`. النقد ونقاط الولاء يعملان بالكامل.
- تغيير كلمة المرور يبطل الجلسة بحسب سلوك الخادم، لذلك يعيد التطبيق المستخدم إلى صفحة الدخول.
- لا يختار الزبون السائق؛ الإدارة تعيّنه بعد تأكيد طلب التوصيل.

## متطلبات الإطلاق المتبقية

لا تُحفظ أسرار الإنتاج داخل المصدر. يلزم عند النشر فقط: رابط API نهائي عبر HTTPS، مفتاح توقيع Android، حساب وشهادات Apple، ورابط مزود خرائط مصرح للاستخدام التجاري.
